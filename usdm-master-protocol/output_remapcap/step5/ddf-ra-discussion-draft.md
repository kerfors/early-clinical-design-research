# Mapping a three-layer master protocol (REMAP-CAP) to USDM v4.0.0: what works, what breaks

I tried to map a real master protocol with three document layers into USDM v4.0.0, using only the published documents. I first tried the Lilly Chronic Pain Master Protocol, but its disease-state addenda are not public. So I used REMAP-CAP, which publishes all layers and all versions:

- Core Protocol 4.0, the master;
- the Patient, Pathogen and Disease Appendix (PANDA) 1.0, the population layer;
- the Corticosteroid Domain-Specific Appendix 6, which holds the interventions.

I added Core Protocol 4.1 as an amendment. The result is USDM JSON validated against the published model (structure and DDF value sets), a mapping log with document evidence for each value, and a table of 21 breakpoints.

## What works

- The document hierarchy: the Core Protocol has `childIds` to PANDA and to the domain appendix (#614).
- Shared eligibility criterion items at StudyVersion level, referenced by the design.

## What breaks

1. **Inherited content can only be copied.** The domain appendix takes 19 things from the Core, for example the primary endpoint, platform eligibility, trigger thresholds and the allocation cap. Endpoint is composed in its objective, so the Core endpoint must be copied into the domain design. The link to the Core is lost.
2. **Defaults and delegation.** The Core gives defaults that a domain appendix may override ("unless otherwise specified in a DSA", 6 statements) and hands content to the appendices (15 statements). There is no place for this in the model.
3. **No version binding between layers.** The domain appendix refers to "the Core Protocol" without a version. Core 4.1 changed the primary endpoint, so the effective endpoint of the unchanged appendix changed too. Core 4.1 even has a transition rule for appendices dated before it. A StudyChange can only point to Core sections, and `DocumentContentReference.appliesToId` points to the document, not to a version.
4. **No unit for a domain or substudy, and no class for strata.** The domain becomes a StudyDesign. The Core cannot be one, because arms, cells and epochs are required. Age strata and illness states (dynamic, with re-randomisation) have no class.
5. **The M11 mapping is behind #614.** Both the DDF-RA v4.0.0 M11 mapping and the HL7 Clinical Study Protocol IG ballot (May 2026) map the Master Protocol Indicator to `StudyDefinitionDocumentVersion.children`, the location before #614.

## Questions for 4.1

- Can an object at design level reference content held elsewhere (in the Core), instead of copying it?
- Should a document version be able to state which version of its parent document it applies to?
- Is there a planned way to express a default that a child document may override?
- Should `DocumentContentReference` point to a document version?
